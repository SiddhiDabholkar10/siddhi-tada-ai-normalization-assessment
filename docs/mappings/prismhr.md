## Company fields

- One company per client (D-034). The client id is the canonical company id and the id of the client's single tax entity (D-042); the tax entity's name is the legal name and its EIN is federalIdNumber, provider-masked (D-024). Country is not sent.
- The client address is the delivery/mailing address (AddressType mailing). Location addresses are work addresses.
- Owned entries take their canonical ids from the client id plus the provider code (pay code, deduction code, location id, pay group code); the code is also copied to the entry's code.
- A pay group that batch lists, vouchers or employees name but getClientCodes and getPayrollSchedule leave out (live: client 134 lists none while its batches name 'Main') is added from the id alone: code = the id, name and frequency not_provided, marked reference_only (D-097). Only ids are read, which are reference rows of the payroll and employee tables.
- is_active of pay and deduction codes: only an obsoleteDate is sent, and comparing it with today would make output depend on the run date (D-036), so is_active is null with not_provided and the date stays in provider_extensions. Pay groups send no active flag either.
- getClientCodes also holds employee label tables (status, type, job, department, division and other codes); they are classified with the employee step (D-064), so the route stays pending until then.

## Employee fields

- One Employee per (client, employee id) (D-039). getEmployeeList enumerates the ids of a client; getEmployee is called with all 14 options. The canonical id is built from the client id and the employee id.
- Step 3a covers profile, employment, job and compensation; step 3b-1 the tax settings and I-9 fields of the compensation block; step 3b-2 emergency contacts, health, skills and education, events, new hire questions and enrollment flags, plus getPaidTimeOff and getDependents. Step 4 (D-081): the directDeposit block maps to DirectDeposit records (direct_deposit.json); the hsa block (HSA contribution transfer accounts, not net pay deposits) and cafeteriaPlan stay on the employee as extensions; scheduledDeduction is excluded (getScheduledDeductions is the source).
- Related people (step 3b-2): one RelatedPerson per dependent[] item (getDependents) and per emergencyContact[] item (getEmployee), never merged by name. A flag the source does not state (is_emergency_contact on a dependent; is_dependent and is_beneficiary on an emergency contact) is not_provided, not false.
- Tax withholding (step 3b-1): one federal setting per employee (level federal, jurisdiction 'US', residency not_applicable), one state setting per stateTax[] entry and one local setting per localTax[] entry (residency not sent: not_provided). PrismHR sends no exempt claim and no additional percent: is_exempt and additional_percent are not_provided. Override type B sets is_blocked; A fills additional_amount; F (fixed amount) and P (percentage) have no typed home, so additional_amount is not_applicable and the raw type and amount are kept in sensitive_provider_extensions. Extras of the withholding settings go to sensitive_provider_extensions, because the whole tax_withholding part is sensitive (D-040).
- Work authorization (step 3b-1, review fix; 3b-2 amendment): is_nonresident_alien (from nonResAlien) and i9_on_file (from formI9Filed, 'Form I-9 is on file': not completed) are typed. formI9RenewDate (renewal date, not a document expiration) and alienRegExpDate go to sensitive_provider_extensions; i9_completed, i9_completed_date, document_expiration_date and visa_type are not_provided.
- Addresses come from getAddressInfo (home, W-2 and alternate mailing, with county). The copies inside getEmployee are excluded as duplicates: home equal for 6 of 6 sampled employees; W-2 and alternate empty on both routes for 6 of 6.
- History sources (D-069): employment_history from getStatusHistoryForAdjustment; compensation_history from getPayRateHistory; job_history from the getHistory position, department, division and location changes. The getHistory pay changes equal the pay rate history (65 of 65 rows in 2 employees, all values) and its status and leave entries equal the status history (3 of 3), so those copies are excluded; their reasons fill employment_history[].reason, joined by effective date and status code.
- Client-defined codes (status, type, job, department, division, project, ethnic, reason, relation) keep the code as raw_code and take labels from getClientCodes (D-064). Their canonical value comes only from a documented class or report code, never from the code or its words.
- Org unit type comes from the source field (homeDepartment department, homeDivision division, projCostCenter project, subCostCenter cost_center; documented by the field descriptions); the field name is the raw_code.
- Pay frequency joins compensation.payGroup to the getPayrollSchedule letter of that pay group (prismhr.pay_period, documented, D-041 amendment 2). Without a matching schedule: null, not_provided and a diagnostic; payPeriod stays in provider_extensions.
- Termination date is the status date when statusClass is T; termination type and reason are read only for terminated employees, otherwise not_applicable. PrismHR sends no rehire date: rehire_date is null with not_provided, and hire_date is lastHireDate (the current employment).
- Currency is not sent; USD is assumed (CANONICAL_MODEL 1.5).

- getDeductions is the documented setup source (D-048): one DeductionSetup per employeeDeductions.deduction[] item, source_basis documented_assignment, id from (client, employee, deductionCode); a code repeated in one response adds the position with an unstable_id diagnostic. getVoluntaryRecurringDeductions is deselected: its records equal the type V records of getDeductions (8 of 8, D-081).

- Garnishments: getGarnishmentDetails returned 403 for the demo user (6 of 6), so its rows come from the spec. - Arrears (getDeductionArrears): each entry is kept in the provider_extensions of the setup with the same deduction code (join; 26 of 26 live entries match the employee's LTD setup). An entry that matches no setup is not dropped: the Phase 5 adapter keeps it in Employee.provider_extensions.
